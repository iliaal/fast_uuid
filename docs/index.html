fast_uuid

RFC 9562 UUID generation as a PHP C extension. Versions 1, 2, 3, 4, 5, 6, 7, 8 plus nil and max, a ramsey/uuid-shaped object API, and procedural functions that skip object allocation. Every example below was run against the built extension; the output shown is what it printed.

Install

# build the extension
phpize && ./configure --enable-fast-uuid && make && make test

# or with PIE
pie install iliaal/fast_uuid

# the ramsey-compat layer (optional, separate package)
composer require iliaal/fast-uuid-compat

No external libraries. v1 and v6 use an internal RFC-compliant generator with a random node (multicast bit set); v3 and v5 use PHP's bundled MD5 and SHA1.

Quick start

use FastUuid\Uuid;

// generate
echo Uuid::uuid4();                 // random
echo Uuid::uuid7();                 // time-ordered, good DB key

// parse and read back
$u = Uuid::fromString('6ba7b810-9dad-11d1-80b4-00c04fd430c8');
echo $u->getVersion(), ' ', $u->getHex();

019e8314-69c9-738a-aea4-8a72d37418eb
1 6ba7b8109dad11d180b400c04fd430c8

Generating UUIDs

Each factory returns a FastUuid\Uuid. Cast to string or call toString() for the canonical form.

// time-based and random
Uuid::uuid1();   // node + clock, optional Uuid::uuid1($node, $clockSeq)
Uuid::uuid6();   // reordered-time, sortable v1
Uuid::uuid4();   // random
Uuid::uuid7();   // unix-time-ordered, optional Uuid::uuid7($dateTime)
uuid1  60e596ac-5db2-11f1-aea4-a92f0e25fb04   (sample)
uuid6  1f15db26-0e59-66ad-aea4-a92f0e25fb04   (sample)
uuid4  36fa4138-9c2e-4765-955e-161592900197   (sample)
uuid7  019e8314-69c9-738a-aea4-8a72d37418eb   (sample)
// name-based (deterministic): v3 = MD5, v5 = SHA1
Uuid::uuid3(Uuid::NAMESPACE_DNS, 'php.net');
Uuid::uuid5(Uuid::NAMESPACE_DNS, 'php.net');
11a38b9a-b3da-360f-9353-a5a725514269
c4a760a8-dbcf-5254-a0d9-6a4474bd1b62
// DCE Security (v2): local id in bytes 0-3, domain in byte 9
$u = Uuid::uuid2(Uuid::DCE_DOMAIN_PERSON, 1000);
echo $u->getVersion(), ' ', $u;

// v8: caller supplies 16 bytes, version and variant get set
echo Uuid::uuid8(hex2bin('00112233445566778899aabbccddeeff'));
2 000003e8-5db2-21f1-b700-5975aec1a10d   (local id 1000 = 0x000003e8)
00112233-4455-8677-8899-aabbccddeeff

Parsing and conversion

fromString accepts the canonical form, a urn:uuid: prefix, brace-wrapped, bare 32-hex, and any letter case. A bad string raises FastUuid\Exception\InvalidUuidStringException.

$s = '6ba7b810-9dad-11d1-80b4-00c04fd430c8';

Uuid::fromString($s);
Uuid::fromBytes(hex2bin('6ba7b8109dad11d180b400c04fd430c8'));
Uuid::fromInteger('143098242404177361603877621312831893704');
Uuid::fromHexadecimal('6ba7b8109dad11d180b400c04fd430c8');
Uuid::isValid($s);            // bool
fromString       6ba7b810-9dad-11d1-80b4-00c04fd430c8
fromBytes        6ba7b810-9dad-11d1-80b4-00c04fd430c8
fromInteger      6ba7b810-9dad-11d1-80b4-00c04fd430c8
fromHexadecimal  6ba7b810-9dad-11d1-80b4-00c04fd430c8
isValid          true   (false for 'nope')
// fromDateTime builds a v1 at the given instant
$u = Uuid::fromDateTime(new DateTimeImmutable('2024-01-01 00:00:00'));
echo $u->getVersion(), ' ', $u->getDateTime()->format('Y-m-d');
1 2024-01-01

Reading a UUID

$u = Uuid::fromString('6ba7b810-9dad-11d1-80b4-00c04fd430c8');

$u->getHex();        $u->getUrn();      $u->getBytes();   // 16 raw bytes
$u->getVersion();    $u->getVariant();  $u->getInteger();
$u->getFields();     $u->getDateTime();
$u->equals($other); $u->compareTo($other);

// ramsey/identifier-style aliases of the four get* converters above
$u->toBytes();      $u->toHexadecimal();   $u->toUrn();   $u->toInteger();
getHex      6ba7b8109dad11d180b400c04fd430c8
getUrn      urn:uuid:6ba7b810-9dad-11d1-80b4-00c04fd430c8
getVersion  1        getVariant  2
getInteger  143098242404177361603877621312831893704
getFields   {"time_low":"6ba7b810","time_mid":"9dad","time_hi_and_version":"11d1",
             "clock_seq_hi_and_reserved":"80","clock_seq_low":"b4","node":"00c04fd430c8"}
compareTo   -1   (00..01 vs 00..02)

toBytes(), toHexadecimal(), toUrn() and toInteger() are aliases of getBytes(), getHex(), getUrn() and getInteger(), following the get*→to* naming of the newer ramsey/identifier library.

getDateTime() works for the time-based versions (1, 2, 6, 7) and raises UnsupportedOperationException for the others. The object is JsonSerializable and Stringable, so it drops straight into json_encode:

echo json_encode(['id' => $u]);
{"id":"6ba7b810-9dad-11d1-80b4-00c04fd430c8"}

Procedural functions

These return a string with no object allocation. Use them on the hot path: ORM inserts, cache keys, bulk generation.

uuid_v1(); uuid_v3($ns, $name); uuid_v4(); uuid_v5($ns, $name);
uuid_v6(); uuid_v7(); uuid_v8($bytes);
uuid_v4_fast();                  // non-crypto xoshiro256**, IDs only
uuid_to_bin($s);                 // canonical -> 16 bytes
uuid_from_bin($bytes);           // 16 bytes -> canonical
uuid_is_valid($s);
fast_uuid_random_bytes(16);      // batched CSPRNG bytes
uuid_v4         fbc41d54-b200-43d8-891c-b9c1a92df715   (sample)
uuid_to_bin     6ba7b8109dad11d180b400c04fd430c8       (hex of bytes)
uuid_from_bin   6ba7b810-9dad-11d1-80b4-00c04fd430c8
uuid_is_valid   true
uuid_v4_fast() uses a non-cryptographic PRNG. Don't use it for session tokens, password-reset keys, or anything an attacker shouldn't predict. Use uuid_v4() for those.

ramsey-compat layer

The FastUuid\Compat package puts a ramsey/uuid-shaped API over the C core. Migration is largely a use swap from Ramsey\Uuid\Uuid to FastUuid\Compat\Uuid. Generation stays on the C fast path.

use FastUuid\Compat\Uuid;

// factories return the per-version class
Uuid::uuid4() instanceof FastUuid\Compat\Rfc4122\UuidV4;   // true

// Fields and Type objects
$u = Uuid::fromString('6ba7b810-9dad-11d1-80b4-00c04fd430c8');
(string) $u->getFields()->getNode();   // Type\Hexadecimal
(string) $u->getInteger();              // Type\Integer
instanceof UuidV4   true
getNode             00c04fd430c8
getInteger          143098242404177361603877621312831893704
use FastUuid\Compat\Codec\OrderedTimeCodec;
use FastUuid\Compat\Guid\Guid;
use FastUuid\Compat\UuidFactory;
use FastUuid\Compat\Provider\RandomGeneratorInterface;

// codec round-trip (MySQL ordered-time layout)
$c = new OrderedTimeCodec();
$c->decodeBytes($c->encodeBinary($v1))->equals($v1);   // true

// GUID mixed-endian presentation
(new Guid($u))->toString();

// swap the random source on a factory
$f = new UuidFactory();
$f->setRandomGenerator(new class implements RandomGeneratorInterface {
    public function generate(int $length): string { return random_bytes($length); }
});
$f->uuid4()->getVersion();   // 4
codec round-trip    true
guid                10b8a76b-ad9d-d111-80b4-00c04fd430c8
factory uuid4 ver   4

Benchmarks

Throughput against ramsey/uuid 4.9.2 and the PECL uuid extension 1.3.0, on PHP 8.4.22 NTS (non-debug, x86-64 with the SSSE3 formatter). Best of 5 runs, 500k iterations each. Each engine ran in its own process. Higher is faster.

fast_uuid procedural fast_uuid object uuid_v4_fast (non-crypto) PECL uuid ramsey/uuid

Procedural and PECL paths return a string directly; the object and ramsey paths build an object then format. Compare procedural to PECL and object to ramsey for like-for-like.

Speedup over ramsey/uuid

v137.6x53.8x
v720.1x28.8x
parse3.4x5.5x

The batched CSPRNG drives the v4 gap: getrandom() is amortized across many UUIDs instead of one syscall each. PECL uuid keeps pace on v1 but its v4 draws fresh entropy per call, so it falls to 0.48M. Full method and raw numbers live in BENCHMARKS.md.
